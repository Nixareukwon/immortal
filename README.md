# IMMORTAL — панель управления Twitch-ботом

Twitch-бот и веб-панель для него: команды и таймеры, модерация, баллы и
цитаты — отдельно для каждого канала, музыка для OBS и персональные
приглашения для других стримеров.

## Доступ другим людям с этого ПК

Для временной HTTPS-ссылки без домена используется Cloudflare Quick Tunnel.
Запуск: `start-sharing.cmd` (перед ним остановите обычный `web_panel.py`,
если он занимает порт 8080). Панель и туннель работают, пока запущен этот процесс.
Остановка: `stop-sharing.cmd`; эта команда остановит и запущенный им экземпляр
панели/бота. Не выключайте ПК и не переводите его в сон во время работы.

Для `start-sharing.cmd` нужна утилита `tools/cloudflared.exe` — она не входит
в репозиторий (файл слишком большой). Скачайте cloudflared для Windows на
<https://github.com/cloudflare/cloudflared/releases> (файл
`cloudflared-windows-amd64.exe`) и положите его в папку `tools` под именем
`cloudflared.exe`.

Текущий адрес записывается в `.hosting/address.txt`, отдельный пароль общего
доступа — в `.hosting/password.txt`. Этот пароль используется и локальной
страницей, пока панель запущена через `start-sharing.cmd`; пароль из `.env`
не изменяется. После перезапуска туннеля ссылка обычно меняется, пароль
сохраняется. Не публикуйте файлы `.hosting` и не передавайте `.env`.

Пароль из `.hosting/password.txt` — это вход владельца. Другим людям пароль
передавать не нужно: создайте персональное приглашение в разделе **Доступ к
панели** (см. «Личные пароли для панели»). Запуск и остановка бота, музыка и
приглашения доступны только владельцу; приглашённые настраивают только свои
каналы.

Сервер слушает только `127.0.0.1:8080`; входящий порт на роутере не нужен.
Режим внешнего доступа требует HTTPS-адрес `PANEL_PUBLIC_ORIGIN` и пароль
минимум из 16 символов. Скрипт задаёт их автоматически. Проверки Host,
Origin и CSRF сохраняются. Журналы находятся в `.hosting/panel.log` и
`.hosting/tunnel.log`. Quick Tunnel подходит для временного доступа, а не
для постоянного адреса с гарантиями доступности.

## Название и категория: команды редакторов

В обеих версиях бота редакторы канала и владелец могут отправлять
`!title Новое название` (`!t`) и `!game Just Chatting` (`!g`).
В `bot.py` также работают существующие алиасы категорий. Роль модератора
сама по себе не даёт доступ: бот проверяет актуальный список редакторов Twitch.

Для этого нужен **пользовательский токен владельца канала**. Проще всего не
вписывать его вручную: владелец привязывает свой Twitch прямо в панели
(раздел **Вход через Twitch** ниже) и выдаёт приложению полный список прав —
панель сохранит токен, подставит его боту и будет обновлять сама, пока панель
запущена.

Запасной вариант — отдельный токен в `.env`:

```dotenv
TWITCH_BROADCASTER_TOKEN=oauth:ТОКЕН_ВЛАДЕЛЬЦА
```

Владелец должен авторизовать OAuth-приложение с разрешениями
`channel:manage:broadcast` и `channel:read:editors`.
См. [получение пользовательского токена](https://dev.twitch.tv/docs/authentication/getting-tokens-oauth/).
Client ID определяется из этого токена автоматически; он может отличаться от
приложения чат-бота. `TWITCH_TOKEN` остаётся токеном аккаунта бота для чата.
Без отдельного токена используется `TWITCH_TOKEN`, но только если он принадлежит
владельцу нужного канала и имеет необходимые разрешения.

Для нескольких каналов задайте `TWITCH_BROADCASTER_TOKEN_ИМЯКАНАЛА` отдельно
для каждого (имя канала латиницей, в верхнем регистре) — этот вариант всегда
приоритетнее токена, привязанного через панель.
После настройки ручного токена полностью перезапустите панель/бота. Токен из
панели обновляется автоматически; ручной токен при истечении придётся заменить.

**Одного токена редактора недостаточно:** публичный Twitch API требует токен
владельца для [изменения параметров канала](https://dev.twitch.tv/docs/api/reference/#modify-channel-information).
Без авторизации владельца редактор может менять параметры вручную через
панель управления Twitch; этот бот не автоматизирует браузер Twitch.

Веб-панель запускается локально вместе с ботом и использует ту же базу `bot.db`.
Из браузера можно управлять пользовательскими командами и таймерами, баллами
зрителей, антифлудом, запрещёнными словами, цитатами и алиасами категорий,
а также запускать бота и отправлять сообщения в чат.

## Антифлуд и ограничения чата

Антифлуд в обеих версиях допускает два-три одинаковых сообщения: фильтр
повторов срабатывает на четвёртом за 5 секунд, а для длинных сообщений
(порог `main_size`) — на четвёртом за 12 секунд. Независимые фильтры размера,
капса, ссылок и частоты сообщений продолжают действовать.
После успешного таймаута история сообщений пользователя очищается.
За капс таймаут выдаётся только за третье сообщение с минимум 15 буквами
и долей заглавных от 85% за 10 секунд от одного пользователя в одном канале.
Одиночный капс не вызывает таймаут за заглавные буквы; остальные фильтры
продолжают действовать. После успешного таймаута история капса очищается.
Неудачные запросы таймаута не увеличивают ступень наказания.
Настройка `percent` сравнивает объём сообщений с другими зрителями,
а не задаёт порог капса; 0 отключает это дополнительное условие.

## Музыкальный виджет для OBS

Раздел **Музыка для OBS** доступен только владельцу панели.
Раздел показывает только музыкальные источники.
Приложение Spotify определяется через медиасессию Windows 10/11.
Spotify Web, Яндекс Музыка и **YouTube Music** подключаются через расширение
из папки `music_extension` (Chrome, Edge, Яндекс Браузер).
Обычный YouTube, Twitch и универсальные браузерные медиасессии исключены:
Windows не сообщает надёжно, какой сайт играет в браузере.

1. Установите обновлённые зависимости командой
   `.\.venv\Scripts\python.exe -m pip install -r requirements.txt`.
2. Полностью перезапустите `web_panel.py`, откройте **Музыка для OBS**.
3. Включите виджет и сохраните настройки. Запустите музыку на этом ПК.
4. Для музыки из браузера скачайте расширение в панели и распакуйте архив.
   В управлении расширениями включите режим разработчика и выберите
   «Загрузить распакованное расширение», указав папку с `manifest.json`.
   Можно использовать напрямую папку `music_extension` из проекта.
   Откройте настройки расширения, вставьте **ссылку подключения расширения**
   из панели, сохраните, затем обновите вкладку с музыкой.
   Поддержаны `open.spotify.com`, `music.youtube.com` и `music.yandex.ru/com/kz/by`.
   После начала воспроизведения сервис появится в списке источников панели.
5. Скопируйте ссылку, добавьте в OBS источник **Браузер**, вставьте URL.
   Размер: **520 × 180**, фон прозрачный. OBS должен работать на этом же ПК.

Название и исполнитель обновляются примерно раз в две секунды. Прогресс
показывается, если приложение передало длительность. Обложка берётся из
медиасессии Windows или музыкального сайта и отображается в предпросмотре панели. Если картинки
нет, она недоступна или больше 1 МБ, показывается декоративная пластинка.
По умолчанию виджет скрывается при паузе; это можно
отключить. При потере выбранного источника или связи виджет скрывается.
Автоматический режим выбирает играющий музыкальный источник. Чтобы исключить
переключение между сервисами, выберите конкретный источник в настройках.
При закрытии вкладки данные расширения устаревают через 10 секунд;
виджет скрывается при следующем обновлении (до двух дополнительных секунд).

Виджет изначально выключен. Настройки и персональная ссылка сохраняются в
`bot.db`. Ссылка даёт доступ только к отображаемым данным трека, без доступа
к управлению ботом; не публикуйте её. Ссылка расширения использует отдельный
ключ, который разрешает только передачу музыкальных данных. Не публикуйте
и его. Расширение передаёт название, исполнителя, время и обложку только в
локальную панель; оно не читает страницы Twitch или обычного YouTube.
Для приложения Spotify плеер и панель должны работать в одном
интерактивном сеансе Windows. Виджет не захватывает звук: настройте звук
приложения или рабочего стола отдельно в OBS.

Если трек не найден: включите воспроизведение, проверьте выбранный источник,
попробуйте автоматический режим. Для веб-плеера проверьте статус в расширении
и обновите музыкальную вкладку после установки. Если сайт не передаёт
Media Session metadata, расширение не сможет определить трек.

## Установка и запуск панели

1. Установите Python 3.11 или новее (проект проверен на 3.14) и создайте
   виртуальное окружение:

   ```powershell
   python -m venv .venv
   ```

2. Создайте или заполните `.env` в корне проекта:

   ```dotenv
   TWITCH_TOKEN=oauth:ВАШ_ТОКЕН
   TWITCH_CHANNELS=имя_канала
   PANEL_PASSWORD=придумайте_пароль
   ```

   Для нескольких каналов перечислите их через запятую. Токену необходимы
   разрешения `chat:read` и `chat:edit`. Не публикуйте `.env`.

3. Установите зависимости:

   ```powershell
   .\.venv\Scripts\python.exe -m pip install -r requirements.txt
   ```

4. Запустите панель:

   ```powershell
   .\.venv\Scripts\python.exe web_panel.py
   ```

5. Откройте <http://127.0.0.1:8080>. Если настроен `PANEL_PASSWORD`, войдите
   с этим паролем.

Панель намеренно принимает подключения только с этого компьютера. Чтобы
остановить сервер, нажмите `Ctrl+C` в окне PowerShell.

После изменения Python-файлов полностью перезапустите `web_panel.py`: кнопка
остановки и запуска бота в интерфейсе перезапускает соединение с Twitch, но
не перечитывает уже импортированный код.
## Личные пароли для панели

Владелец входит с логином `owner` (либо оставляет логин пустым) и прежним паролем панели.
Откройте **Доступ к панели → Создать приглашение** и отправьте полученную ссылку человеку.
Он задаст свой логин и пароль длиной от 12 символов. Приглашение одноразовое, действует 24 часа.
Аккаунты сохраняются в `bot.db`; пароли хранятся как PBKDF2-хеши с индивидуальной солью.
Запуск и остановка бота, а также музыкальный виджет OBS доступны только владельцу панели. Приглашённые настраивают только свои каналы (см. «Каналы бота»). Создавать приглашения и отзывать доступ тоже может только владелец.
Кнопка **Отозвать доступ** удаляет аккаунт и завершает его активные сеансы. Для восстановления доступа создайте новое приглашение.
Пароль владельца из `.hosting/password.txt` приглашённым передавать не нужно.
После перезапуска временного Cloudflare-туннеля адрес меняется: создавайте новые ссылки с актуальным адресом.

## Вход через Twitch

На странице входа есть кнопка **Войти через Twitch**. Она работает по коду
устройства: панель получает у Twitch одноразовый код, вы вводите его на
`twitch.tv/activate`, и вход выполняется без пароля. Обычный редирект не
используется, поэтому адрес панели не важен: временный адрес Cloudflare Quick
Tunnel можно перезапускать сколько угодно раз — вход через Twitch продолжит
работать. Само приложение Twitch уже связано с проектом через
`TWITCH_CLIENT_ID` в `.env`; дополнительно настраивать нечего.

Чтобы привязать Twitch, войдите как обычно и откройте **Доступ к панели →
Мой Twitch → Привязать Twitch**. Владелец привязывает свой Twitch и входит им
с полными правами; приглашённые привязывают свои аккаунты сами. Один
Twitch-аккаунт можно привязать только к одному аккаунту панели; повторная
привязка заменяет прежний Twitch у этого аккаунта. Отвязать Twitch можно на
той же странице, а при отзыве доступа привязка удаляется автоматически.
Вход по паролю продолжает работать всегда.

При привязке **владельца** Twitch показывает полный список прав приложения
(управление эфиром, модерация, статистика и другое). Панель сохраняет
полученный токен, подставляет его боту как `TWITCH_BROADCASTER_TOKEN` и
обновляет автоматически, пока панель запущена, поэтому для `!title` и `!game`
ручные токены из `.env` больше не нужны. Если панель не запускалась дольше
30 дней, Twitch аннулирует токен — привяжите Twitch заново. Отвязка удаляет
сохранённый токен, а ручной `TWITCH_BROADCASTER_TOKEN` из `.env` снова
вступает в силу.

Если при подтверждении кода или при обновлении токена Twitch вернёт ошибку,
добавьте в `.env` строку `TWITCH_CLIENT_SECRET=секрет_приложения` (в консоли
приложения на dev.twitch.tv, рядом с Client ID) и перезапустите панель. Для
публичного режима device flow секрет не обязателен.

## Каналы бота

Каналы из `TWITCH_CHANNELS` (`.env`) бот обслуживает всегда: они считаются
каналами владельца, и подключать или отключать их может только он (правкой
файла). Дополнительные каналы подключаются из панели: откройте **Обзор** и в
карточке «Состояние бота» нажмите **Подключить канал**. Канал больше не
вводится текстом — панель открывает окно Twitch (device flow): нужно войти
на twitch.tv в аккаунт самого канала и ввести код. Так подтверждается, что
канал действительно ваш, и опечатка или чужой канал подключены быть не могут.

Приглашённый может подключить только канал, совпадающий с его привязанным
Twitch-аккаунтом, поэтому ему нужно сначала привязать Twitch в разделе
**Доступ к панели**. Владелец может авторизоваться под аккаунтом любого
канала. Токен канала не сохраняется — вход нужен только для подтверждения
владения.

Приглашённый видит и настраивает только свои каналы: списки каналов, отправка
сообщений, настройки и модерация ограничены ими. Владелец управляет всеми
каналами. Крестик рядом с каналом отключает бота от него (для каналов из
`.env` крестика нет). Если бот уже запущен, он заходит в добавленный канал
сразу; после перезапуска все каналы подключаются автоматически. Реестр
каналов панели хранится в таблице `panel_channels` базы `bot.db`.

## Настройки по каналам

Все настройки бота разделены по каналам: настройка одного канала не влияет
на остальные. Канал переключается в сайдбаре: нажмите на карточку канала
(«Ваш Twitch-канал») и выберите нужный из списка — выбор действует во всех
разделах панели (**Команды**, **Таймеры**, **Зрители и баллы**, **Модерация**,
**Цитаты**, **Категории**).

Раздельно хранятся и применяются:

- пользовательские команды и их алиасы (до 30 на канал);
- таймеры — каждый отправляется только в свой канал (до 5 активных на канал);
- баллы зрителей и команды `!points`, `!daily`, `!top`, `!gamble`, `!give`;
- пользовательские запрещённые слова (до 30 на канал), антифлуд уже был
  отдельно на канал;
- алиасы категорий и цитаты.

Настройки отключённого канала сохраняются в базе: если подключить канал
снова, всё вернётся. Старые общие записи при обновлении относятся к каналу
из `TWITCH_CHANNELS` (или к первому подключённому).
